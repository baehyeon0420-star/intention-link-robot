## 3쪽 — 개발 배경: 어떤 문제인식에서 시작했나 (창의성)

- 손 기반 자연 입력이 XR·로봇 제어의 주류가 되고 있으나, **카메라 기반 손 추적은 손이 다른 손·몸·물체에 가려지거나 미세 동작일 때 입력이 끊긴다.** 선택·유지·해제처럼 짧고 명확한 의도가 필요한 순간에 누락이 생기면 신뢰도가 무너진다.
- 그 공백을 근전도로 메우려면 근전도가 **누가 착용해도** 동작해야 하는데, 같은 동작에도 사람마다 신호 크기가 **최대 2.3배** 다르다(s2 2,599 vs s3 1,108).

→ "카메라 대신"이 아니라 "**카메라가 놓칠 때 이어받는**" 입력이 필요하고, 그러려면 근전도 경로가 먼저 믿을 만해야 한다.

## 4쪽 — 아이디어 · 목표 시스템 (창의성 30)

**하이브리드 전환 구조**
```
              ┌ 손이 보임 ──→ 카메라 트래킹 (손가락별 각도) ─┐
웹캠 프레임 → 판단│                                          ├→ 로봇손 (의도를 즉시 표시)
              └ 손이 안 보임 → 근전도 트래킹 (쥐기/놓기 의도) ─┘
```

**기존 방식과의 차이**
| | 카메라 단독 | 근전도 단독 | **본 작품** |
|---|---|---|---|
| 손가락별 정밀 제어 | ○ | ✕ | ○ (보일 때) |
| 손이 가려질 때 | ✕ 끊김 | ○ | ○ 근전도로 이어받음 |
| 힘의 세기·의도 | ✕ | ○ | ○ |
| 착용자 바뀔 때 | 무관 | 개인차 큼 | 10초 보정 + 다중 조건 학습 |

**목표**: 어느 경우에도 의도가 끊기지 않는 입력. 이번 단계는 폴백인 근전도 경로를 먼저 검증하고, 카메라 경로와 전환까지 실물로 연결.

## 5쪽 — 작품 구성 (기술성)

**흐름**: 전극 3개 → MyoWare 2.0 → ESP32(GPIO34, 12bit ADC, 500Hz) → USB 시리얼 → Python 파이프라인 ← 웹캠(MediaPipe) → USB-TTL → AmazingHand(Feetech SCS0009 × 8, 손가락 4개)

| 모듈 | 역할 |
|---|---|
| `serial_reader` | raw 수신, EMA 평활, 세션 기준 정규화, REST/LIGHT/STRONG/GRIP 판정 |
| `calibration` | 세션 시작 시 rest 3초·최대수축 3초 자동 측정 |
| `ml_classifier` | 200ms 윈도우 5특징 + 로지스틱 회귀 추론 |
| `command_mapper` | 상태 → Release / Hold / GripClose |
| `amazinghand_driver` | 전체 자세 및 **손가락별**(`set_fingers`) 서보 각도 전송 |
| `hybrid_demo` | 카메라 손가락 굽힘값 추출, 손 소실 감지, 카메라↔근전도 전환 |

## 6쪽 — 개발 세부 ①: 신호처리·판정 + 데이터 품질 관리 (기술성)

**신호처리**
- 200ms(20샘플) 슬라이딩 윈도우, 50% 오버랩 / MAV·RMS·STD·WL·ZC 5특징
- StandardScaler + 로지스틱 회귀(계수 5개+절편) → 서버 없이 로컬 실시간 추론
- RF 89.2% vs LogReg 86.9%: 경량·이식성으로 LogReg 채택
- **이원화 판정**: 경로A 임계값(즉각 반응, 실제 로봇 제어) + 경로B ML(개인차 보완·검증)

**데이터 품질 관리 — 수집 파이프라인에서 찾아 고친 것** ✅
| 발견 | 원인 | 조치 |
|---|---|---|
| 측정 시작 직후 7초 전 데이터가 읽힘 | OS 시리얼 버퍼 누적, `reset_input_buffer` 미작동 | 상시 수신 스레드 → 지연 **7,840ms → 2ms** |
| ADC 상한(4,095) 넘는 21,924 유입 | 시리얼 줄 깨짐 | 범위 밖 폐기 |
| 10초 연속 수축 시 4,092→42 붕괴, 파일 전체가 grip 라벨 | 근피로 또는 전극 밀림 | 3초×6회 + 회차별 실시간 감시 (추세 −0.79 → +0.03) |
| 로봇 USB 연결 시 rest 잡음 3배 | 노트북 USB 접지 공유 | 세션 캘리브레이션으로 상쇄 (근본: 접지 분리) |

## 8쪽 — 검증 ②: 수집 조건이 다르면 모델이 작동하지 않는다 (기술성, 발표의 정점)

같은 사람·같은 날·같은 펌웨어로 조건만 다른 세 세션 수집.

| 세션 | 로봇 USB | rest 잡음(std) |
|---|---|---|
| A | 분리 | 5.9 |
| B, C | 연결 | 19.5 |

**발견** ✅: A로 학습 → B·C 평가 시 **0.643 — 실제로는 모든 입력을 grip으로 판정**, rest를 한 번도 못 맞춤
**원인** ✅: 조용한 조건으로 학습한 모델은 "rest = 흔들림 없음"으로 기준을 잡아 잡음 큰 rest를 전부 수축으로 판정. **반대 방향은 0.985~1.000** — 한쪽만 실패하는 비대칭이 원인을 확정
**해결** ✅: 특징 변경 무효 → **두 조건을 섞어 학습, 미학습 세션 평가 → LogReg 99.6%**

**설계 원칙**: 학습·보정 데이터는 실사용 조건에서, 여러 번 착용해서 받는다.
**한계**: 1인·3세션. 11월까지 피험자 확대.

## 9쪽 — 구현 결과 (완성도 20)

**1단계 — 근전도 경로** ✅
세션 캘리브레이션 + 임계값 경로로 로봇 연결 상태에서 실물 파지 구동 (영상)

**2단계 — 카메라 경로와 전환** ✅ (9/12 확인)
- 웹캠으로 엄지·검지·중지·약지 굽힘값 추출 → 로봇 손가락별 1:1 제어
- 손이 사라지면 약 0.3초 후 근전도로 전환, 쥐기/펴기 유지, 손이 다시 보이면 복귀
- 서보 명령은 변화 시에만·초당 10회 이하 (버스 포화 방지 검증)

**3단계 — 11월까지** ▶
- 압력센서(FSR400 ×3) 폐루프 파지: 접촉까지 닫기 / 힘 상·하한 / 잡으면 유지
- 근전도 모드 개선: 카메라가 마지막으로 본 손 모양을 기억, 근전도는 오므림 세기만 결정
- ML 모델을 새 조건(500Hz, 로봇 연결, 다중 착용) 데이터로 재학습

**자료**: 근전도 구동 영상 스틸 / 카메라 손가락별 제어 스틸 / 전환 장면(CAMERA→EMG 오버레이)

## 10쪽 — 11월 시연 구성 · 상용화 (상품성 10, 완성도)

**부스 체험 (1인 약 3분)**
1. 전극 부착 → 10초 캘리브레이션
2. 웹캠 앞에서 손 움직임 → 로봇손이 손가락별로 따라 함
3. **손을 상자에 넣거나 등 뒤로 숨김** → 화면 CAMERA→EMG → 주먹 쥐면 로봇도 쥠
4. 손 꺼내면 카메라 복귀 / (압력센서 완료 시) 물건 집어 올림

**보여줄 것**: 실시간 신호·입력 소스·판정 상태 화면, 문제→검증→해결 패널, 백업 영상

**상용화 시나리오**
- 의수·보조기기: 손이 주머니·가방·물체에 가려진 상황에서도 조작 연속성 유지
- 원격 로봇 조작: 작업자 손이 장비에 가려지는 현장
- 부품비 100만 원 이하(MyoWare + ESP32 + AmazingHand + 웹캠), 착용 후 10초 보정으로 누구나

## 11쪽 — 한계 · 확장

**한계 (정직하게)**
- 세션 실험은 1인·3세션 — "이 사용자에게서 확인"까지가 정확
- 근전도 모드는 손가락 개별 제어 불가(1채널) — 전체 쥐기/펴기
- 로봇 USB 접지 간섭: 세션 보정으로 동작하나 표현 범위 1/3로 축소 → USB 아이솔레이터로 해결 예정
- ML 모델은 새 펌웨어 데이터로 재학습 전(현재 실물 구동은 임계값 경로)
- 원 보고서 데이터(100Hz)와 새 데이터(500Hz)는 펌웨어가 달라 직접 비교 불가 → 펌웨어 버전 관리 도입

**확장**
- 2채널 근전도 → 가려진 상태에서도 주먹/집기 구분
- 압력센서 폐루프 → 근전도는 의도, 힘은 센서가 보장 → 사용자 보정 오차에 강건
- 피험자 확대 → 다중 조건 학습 원칙의 일반화 검증
- XR 기기 카메라를 웹캠 자리에 → 1인칭 하이브리드 입력
